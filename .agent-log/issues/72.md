# #72 [flaky] e2e: CI sign-in eats the 15 s budget; touch drag moves before long-press activates
Status: done
PR: #73
Summary: CI e2e test timeout is 30 s (still 15 s locally), because sign-in alone takes ~9 s on CI according to the trace of run 41811484104. `week.spec.ts`'s touch `dragTo` now waits for the drag to really start (`body.style.cursor === 'grabbing'`) instead of a fixed 500 ms before moving. No app code changed.

## What changed
- playwright.config.ts: `timeout: process.env.CI ? 30_000 : 15_000`.
- e2e/week.spec.ts: `waitForFunction` on the grabbing cursor after `touchStart`.

## Tried and rejected
- Calling it an undo bug (#50): the cascade-undo trace shows every step passing, including Undo's click. The budget ran out on the last expect.
- Reproducing with CPU throttle (6×) or network latency: base passes under throttle. ≥300 ms latency fails *everything* (sign-in takes ~13 s), so it's not a targeted repro.

## Notes for future agents
- Read CI traces with `gh run download <id> -n playwright-report`, then parse `test.trace` (JSON lines; `before` events have `startTime` and `title`).
- Open PRs from before this fix will stay flaky on these specs until they merge `feat/cloud-sync`.
