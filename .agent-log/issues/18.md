# #18 Remove the stray Tab stop in every row's checkbox
Status: done
PR: #31
Summary: Gave the checkbox's inner `motion.span` (which keeps `whileTap`) `tabIndex={-1}`, so the checkbox is one Tab stop; added a component test for it.

## What changed
- src/components/Checkbox.tsx: framer-motion gives any element with `whileTap` a `tabindex="0"`
  unless one is set, so the inner box span was an unnamed Tab stop in every row. `tabIndex={-1}`
  on that span stops it; the tap animation and everything else are unchanged.
- src/components/Checkbox.test.tsx: asserts exactly one element with tabIndex >= 0 (the
  role=checkbox button), checked and unchecked. Fails on the old code (2 focusable elements).

## Tried and rejected
- `whileTap` on the `<button>` (as `motion.button`, like TaskItem's chevron): unit tests and
  local e2e passed, but CI e2e failed deterministically (run + retry) on
  `deadline-completed.spec.ts` (desktop). After unchecking a row that had just moved to
  Completed, the CI screencast shows it reopen (0/2) and then complete again about 0.5s later.
  Exact cause unconfirmed: it couldn't be reproduced locally (12/12 repeats), and Firestore
  writes have no bodies in the trace. It's likely tied to the whole 44px hit area scaling or to
  framer's press handling on the button while the row moves between sections.
- CSS `:active` scale on `.box`: framer's inline `transform` from `animate` would override it.

## Notes for future agents
- Any `whileTap`/`whileFocus` on a non-focusable motion element makes it focusable; pass
  `tabIndex={-1}` or put the gesture on the real control (and run e2e in CI before trusting it).
- Mouse-clicking the box still focuses the span (tabindex -1), not the button, as before.
- Local e2e with Docker on 8080: run Firestore on another port with a scratch firebase.json
  (`emulators:exec --config <scratch>`) and temporarily change the port in src/lib/firestore.ts.
  Don't commit either.
