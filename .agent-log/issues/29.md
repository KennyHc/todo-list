# #29 Command palette: tighter fuzzy matching for short queries
Status: done
PR: #32
Summary: fuzzyMatch no longer falls back to a scattered-letter subsequence for queries under 4 non-space characters ("lis" stops matching "b·l·og … offl·i·ne ·s·ync"); longer queries keep the existing substring > word-start > subsequence tiers, so contiguous matches still rank above scattered ones.

## What changed
- `src/lib/fuzzy.ts`: `MIN_SUBSEQUENCE_QUERY = 4`; if the whitespace-stripped query is shorter,
  return null after the substring and word-start tiers. Doc comment updated.
- `src/lib/fuzzy.test.ts`: tests for the short-query rule ("lis", "bk", "b k" → null; "lin"
  substring and "bps" initials still match), for contiguous-over-scattered ranking with
  4+ char queries, and old 2–3 char subsequence examples moved to 4-char queries.

## Callers (grep `fuzzy` in src)
- `src/components/CommandPalette.tsx`: task titles (line ~270) and command labels (~278).
  Both just drop null matches and sort by score, so no palette change was needed.
- Recent items: shown only on an empty query, no fuzzy call, so unaffected.
- e2e: only `week.spec.ts` types in the palette (`week`, a substring) — unaffected.

## Tried and rejected
- Penalising scattered matches instead of dropping them: the issue asks that they not count,
  and with few tasks a penalised match still shows up.

## Notes for future agents
- "Under 4 characters" is measured after trimming and removing inner whitespace, same as the
  word-start and subsequence tiers see it.
- Ranking for 4+ chars was already tiered (substring 3000+, word-start 2000+, subsequence 1000+),
  so "contiguous above scattered" needed tests, not new scoring.
