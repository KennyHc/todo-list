# #21 Esc must not throw away a note draft
Status: done
PR: pending
Summary: Esc in the note editor now saves the draft (same path as blur and ⌘/Ctrl+Enter) and keeps the row selected; the editor shows a "⌘↵ to save · Esc to close" hint and uses the body font instead of the textarea's monospace default.

## What changed
- src/components/TaskNote.tsx: Esc shares the ⌘/Ctrl+Enter branch, so it calls `save()`. The
  editor then shows the note read-only, or closes if the draft is empty. `preventDefault` stays,
  so the global Esc in useHotkeys (which skips defaultPrevented events) doesn't clear the row
  selection. Added a hint `<p>` (wired as `aria-describedby`) showing `⌘↵` on Apple platforms and
  `Ctrl+Enter` elsewhere, via `isMac()`. The hint is hidden on touch devices (`useIsTouch`).
- src/components/TaskNote.module.css: `font-family: inherit` on the note and editor. Without it,
  the textarea used the browser's monospace default. Added a `.hint` style (11px, muted).
- src/components/Notes.test.tsx: replaced the two "Esc reverts" tests with Esc-saves tests: an
  edited note saves once with an undo, a new draft is kept, and an empty draft adds no note.
  Added tests that Esc keeps the row selected and that the hint is the editor's description.

## Tried and rejected
- Esc cancels plus a "Note discarded · Undo" toast (the review's alternative): the issue picks
  "Esc saves", and that's simpler and consistent with blur.

## Notes for future agents
- The global Esc handler (src/hooks/useHotkeys.ts) skips events whose default is already
  prevented. Any field that handles Esc itself should `preventDefault` to keep the row selection.
- The hint uses literal text, not `<Kbd>` caps, to stay small in the row.
- There's no e2e spec for notes; the flow is covered in Notes.test.tsx.
