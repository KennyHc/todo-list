# #48 Header stats: accessible labels for the progress ring and Load
Status: done
PR: pending
Summary: The header's "3/14" and "Load 21" now read "3 of 14 tasks done" and "21 points left" to screen readers (visually hidden text, the visible digits are `aria-hidden`) and show the same text as a hover `title`; the ring gets it as an SVG `<title>`; what the stats count is unchanged.

## What changed
- src/App.tsx (`Controls`): `doneLabel` / `loadLabel` with singular forms ("1 task", "1 point"); each stat span has `title` plus an `.srOnly` copy.
- src/App.module.css: `.srOnly` (same rules as SettingsPopover's).
- src/components/ProgressRing.tsx: optional `label` prop rendered as `<title>`; the SVG stays `aria-hidden`, so the count span is the one thing announced.
- src/components/HeaderStats.test.tsx: labels, titles and singulars.

## Tried and rejected
- `aria-label` on the plain spans: a span with no role doesn't reliably get its name read, so the text is in the DOM instead.
- Reading the animated digits: AnimatedNumber keeps the outgoing digit in the DOM while it animates out (`popLayout`), so a reader could hear both numbers.
- "Effort left: 22 pts" (the issue's example): Today says "N points done" / "N points left" and Week's aria says "N points", so the header uses "points left".

## Notes for future agents
- `getByText` on these labels also matches the ring's SVG `<title>`; the test queries `{ selector: 'span' }`.
- The Load pill is still `display: none` on phones (≤480px), so phone readers get only the progress label. That was already the case.
- Header layout and the #24 avatar badge are untouched; `.stats > svg` still matches the ring.
