# #63 Restoring a backup with an over-long title, notes or >20 tags wipes the whole restore
Status: done
PR: pending
Summary: `migrateTasksState`, which backup restore and the legacy local import both go through, now clamps titles to 500 chars (`clampTitle`, newly exported from `lib/tree`) and runs tags through `normalizeTags` (≤20, normalized, deduped; non-strings dropped). Notes were already clamped, and the AI import already clamped all three (now under test). An emulator test restores the issue's 77-task backup and the server ends with all 77.

## What changed
- src/store/tasks.ts: title + tags normalization in `migrateTasksState`.
- src/lib/tree.ts: `clampTitle` exported.
- src/lib/backup.test.ts: one test per limit, plus non-string tags and an ordinary task next to bad ones.
- src/lib/ai.test.ts: the AI import keeps title, notes and tag count inside the limits.
- tests/emulator/sync.test.ts: the 77-task restore (643-char title, 50 tags, 30k notes). It fails without the fix (server 0) and passes with it.

## Tried and rejected
- Checking the server with `getDocs` or `getDocsFromServer` straight away: both overlay pending local writes, so they show 77 before the rejection. The test waits for the flush (cache shows 77), then `waitForPendingWrites`, then reads the server.
