# #80 Phone: the keyboard's ✓ / Done key should act like Enter everywhere
Status: done
PR: #82
Summary: On phones Enter in the title editor now saves and opens a new sibling with the keyboard up (as on desktop, `enterKeyHint="next"`), and a new `useImeEnter` hook makes the title editor, composer and tag editor run an Enter tapped mid-word once the composition ends, with the committed word and no double fire.

## What changed
- src/hooks/useImeEnter.ts: `intercept(e)` at the top of onKeyDown + `handlers` (composition start/end) on the input. A touch Enter with `isComposing`/keyCode 229 during a composition is left alone (no preventDefault, so the IME commits the word) and `onEnter` runs in a `setTimeout` after `compositionend`, using the latest render's handler. A real Enter that arrives before that timer replaces it; one within 150 ms after it (module-level, so it covers the next row's editor) is swallowed as an echo. On desktop a composing Enter stays commit-only (CJK convention), now also in the composer and tag editor.
- TitleEditor.tsx: one `enter()` for every device; dropped the touch "done" branch and blur. Empty row + Enter still removes it and finishes.
- TaskInput.tsx (composer): Enter accepts the open tag suggestion or submits, through the hook; `enterKeyHint="enter"`.
- TagEditor.tsx: same, `enterKeyHint="enter"`. ',' is unchanged.
- Tests: new src/components/PhoneEnter.test.tsx (touch sibling path, composing ✓ in title/composer/tag editor, echo Enter, desktop commit-only). AddSubtask.test.tsx's two touch tests asserted the old "done" behaviour; updated to the new one.

## Tried and rejected
- Acting on the composing keydown directly: the IME's compositionend lands afterwards and can re-insert the word into a just-cleared field.
- Also listening for `beforeinput` `insertLineBreak`: not added; it's not reliably sent for single-line inputs and would be a second path to dedupe. compositionend covers the case.
- Switching `enterKeyHint` to "done" on an empty title: changing it live restarts Android's input and can break composition.

## Notes for future agents
- Hand check: built-in browser, 375×812 mobile emulation (touch media query true), auth emulator: composer Enter, rename + Enter → focused new sibling, Enter on the empty row finishes, a dispatched composing-Enter sequence adds "Call mum" once. Real IME, and iOS keyboard persistence across the row switch, could not be checked on a real device.
- Once, on a brand-new account, the very first composer Enter after typing did nothing; it didn't reproduce on a fresh load, and the keydown logged normally afterwards.
- CommandPalette Enter already fires while composing (no guard); left as is. Other inputs are `type="date"`/`color`/file or a native `<form>`.
- Local web-emu needs the placeholder `VITE_FIREBASE_*` env from playwright.config.ts when the worktree has no .env.local.
