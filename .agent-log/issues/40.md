# #40 Repeating tasks: unchecking leaves the spawned copy, so toggling makes duplicates
Status: done
PR: pending
Summary: Reopening a repeating task (toggle, History restore, or a cascade from a subtask) now deletes its spawned copy when the copy is untouched, in the same update and undo entry; if the copy was edited or worked on, the copy stays and the reopened task becomes a one-off (`repeat: null`, toast "· no longer repeats").

## What changed
- src/lib/recur.ts: `isUntouchedCopy(tree, copyId)` checks the copy is exactly what `spawnNextOccurrence` made: open, same parent, due date recomputed from the original with `today = copy.createdAt`, same fields (title, tags, notes, difficulty, colour, repeat, shifted start/due dates, no plan) and the same subtree, every node open with `createdAt` equal to the spawn time. Collapsing is ignored. Extracted `copyRepeat` so spawn and check agree on the monthly anchor.
- src/store/tasks.ts `toggle`: on reopen, for every reopened task (self, descendants, ancestors) that repeats, untouched copies (`spawnedFrom === id`, judged on the pre-toggle tree) are deleted with `deleteTask`; any touched copy makes the original a one-off. History and undo need nothing extra: the copy was open, so it has no History entry, and the undo snapshot is the pre-toggle state.
- Tests: recur.test.ts (`isUntouchedCopy`), tasks.test.ts (reopen removes copy, toggle x5 → one copy, edited copy kept + one-off, copy with a done subtask, repeating parent / cascade reopen, History restore). Clock pinned to Tue 20 Oct 2026.

## Tried and rejected
- Reverse rule (keep original repeating, strip `repeat` from the edited copy): the user edited the copy as the series' next occurrence; taking its repeat away would surprise them more.
- Storing a fingerprint on the copy: needs a new synced field and a rules change; recomputing from `createdAt` is exact without one.

## Notes for future agents
- Undo is single-level (`undoLast` restores only the latest entry).
- A copy that was completed counts as touched, so reopening an older occurrence from History makes it a one-off instead of deleting the later one.
- If the copy was deleted (e.g. Clear completed), nothing is found and the reopened task keeps repeating.
- `src/sync/` untouched; removal goes through the normal store update.
