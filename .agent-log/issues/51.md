# #51 Task rows: one Tab stop per row (roving tabindex, arrow keys)
Status: done
PR: pending
Summary: Each task row is now one Tab stop (roving tabindex on the row, `tabStopId` in the UI store); the Tree is an ARIA `tree` of `treeitem`s, ↑/↓/j/k/Home/End move between rows, → expands or steps into the row's buttons, ← collapses or goes to the parent, and the existing row shortcuts act on the focused row as before.

## What changed
- src/hooks/useHotkeys.ts: keeps `ui.tabStopId` = focused row if shown, else the first row (store subscription). Adds Home/End (`edge`), ← to the parent in the Tree, → into the row's first control (`enterRow`), ←/→ in every row view (was Tree only), and ↑/↓ from a row's own buttons (`inRow`, off while a keyboard drag is active). Exports `TEXT_ENTRY` and `rowControls`.
- src/components/TaskItem.tsx: the row `div` is `role="treeitem"` (Tree, via SortableTaskItem's `tree`) or `role="group"` (other views), `tabIndex` 0/-1, `aria-label` title (+ ", done"), `aria-level`/`aria-expanded`/`aria-selected` in the Tree. `onKeyDown` walks the row's controls with ←/→ (← from the first returns to the row) and Esc returns to the row. Focusing the row (Tab) selects it; DOM focus follows `focusedId` when focus is on nothing or on another row (never from a field or dialog). Every inner control gets `tabIndex={-1}`.
- `tabIndex` prop on Checkbox, TagChip, LinkChip, DifficultyIcon, TaskMenu (trigger), BreakdownNudge; TaskNote's read-only note is `-1` + `data-row-control`.
- TaskList.tsx: `<ul role="tree" aria-label="Tasks">`. TaskItem.module.css: `.row:focus-visible` gets the hover background, the actions and an inset ring.
- shortcuts.ts: "?" sheet lists Home/End, → / ← behaviour and Esc back to the row.
- Tests: matchHotkey cases, two App tests (Tab stops, ←/→ and buttons), e2e/keyboard-rows.spec.ts.

## Tried and rejected
- `role="treegrid"`: needs gridcells around every control and new wrappers in a flex row tuned for #44's hit areas. Kept tree roles but used treegrid's →/← rule (→ on an open row enters its controls instead of APG tree's "go to first child"; ↓ already does that).
- Tree roles in By deadline / Today / Week: their lists mix in section headers; those rows are labelled `group`s with the same roving tabindex instead.

## Notes for future agents
- A new button inside a row must take `tabIndex={-1}`, or it's a Tab stop again; ←/→ reach anything matching `ROW_CONTROLS` in the row's `<li>`.
- Row `onKeyDown` only acts when the target is in `rowControls(li)`, so keys from portaled popovers (which bubble through React) are left alone. ⌘Z/⇧⌘Z are untouched (modifiers skip both handlers).
- Local e2e: 8080 (Docker) and 8181 were taken here; used a scratch firebase.json on 8282 plus a temporary port edit in src/lib/firestore.ts, not committed.
