# #86 [QA] App never notices midnight: Today, overdue and Week stay on yesterday
Status: done
PR: pending
Summary: New `ui.today` (local YYYY-MM-DD, not persisted) kept current by `useToday()` (`src/hooks/useToday.ts`): one shared clock with a timeout to the next local midnight, rescheduled each time, plus a recheck on `visibilitychange` (when visible) and `focus`. The header date, Today/Tomorrow labels, overdue styling and nudge, Week's current week, the Today view and "starting later" now render from it, so they move to the new day without a reload.

## What changed
- `src/store/ui.ts`: `today` + `setToday` (no-op when unchanged); not in `partialize`.
- `src/hooks/useToday.ts`: `useToday()` returns the date and ref-counts one clock (starts on the
  first mount, stops after the last unmount, syncs on start). Also exports `msUntilMidnight`, `syncToday`.
- Render reads switched from `todayISO()`: `App.tsx` (header, via `parseISO`), `DuePill`,
  `TaskList` (flattenTree), `TaskItem` (upcoming/startsLater), `UpcomingFooter`, `TodayList`,
  `DeadlineList` (buckets), `WeekView` (current week + range), `useTodayHint`, `OverdueNudge`.
- `useOverdueIds(tag, today)` now takes `today` (its only caller is OverdueNudge).
- Tests: `useToday.test.ts` (fake timers: midnight twice, visibility, focus, one shared timer);
  DuePill "Tomorrow" → "Today" across midnight. `Upcoming.test.tsx`'s "once its day comes" test
  relied on an edit re-reading the date (the bug); it now fires `focus`.

## Tried and rejected
- Mounting the clock once in App and reading the store elsewhere: components rendered alone
  (tests, a future dashboard) would read a stale date. Ref-counting in the hook avoids that.

## Notes for future agents
- Rule: render against `useToday()`; write paths and event handlers (completion stamps, plan for
  today, `moveOverdueToToday`, Week drop moves, quick-add parsing) keep `todayISO()`.
- Not switched (transient while open, or #80's files): DatePicker/RescheduleMenu/TaskMenu quick
  picks, TaskInput/QuickChips/TitleEditor chips, `store/reveal.ts`.
- The timeout adds 50 ms past midnight; fake-timer tests must advance past it.
- Not verified in a browser; covered by unit/component tests.
