# #24 Show sync and offline status outside the account menu
Status: done
PR: #45
Summary: The account avatar now carries a small badge whenever sync isn't `ready` (grey `--muted` for offline, `--danger` for error), shown by CSS off `<main data-sync>`; the avatar's accessible name gains the status ("Account, Offline — changes will sync") and a visually hidden `role="status"` announces it, plus "Synced" on the way back.

## What changed
- src/components/SettingsPopover.tsx: `[data-sync-badge]` span inside the avatar button; status-aware `aria-label`; sr-only `role="status"` next to the button, empty while synced until the first non-ready state.
- SettingsPopover.module.css: `.button` is `position: relative`; `.syncBadge` hidden by default, shown via `:global(main[data-sync='offline'|'error'])`; ring is `--bg` so it reads on any avatar.
- src/components/SyncBadge.test.tsx: name + announcement for ready / offline → ready / error.
- e2e/sync.spec.ts: `context.setOffline(true/false)` → badge and name appear, then clear.

## Tried and rejected
- "Offline · N changes pending" pill: Firestore only gives a per-doc `hasPendingWrites` flag, so a count means new sync-engine plumbing; the issue allows the dot alone ("and/or").
- Reusing an existing live region: there is no app-wide one (TaskList's is for drag, the menu's `role="status"` only exists while it is open), so the badge gets its own.

## Notes for future agents
- `loading` counts as synced for the badge: SignedIn shows the splash during first load, and sync never goes back to `loading` after that.
- Port 8080 is held by a Docker container on this machine. e2e was run with the Firestore emulator temporarily on 8085 (`src/lib/firestore.ts` + `firebase.json`, reverted): 52 passed. `test:emulators` can't run that way (it still dials 8080). No sync or rules code changed.
- Checked in light and dark at 1280 (desktop project) and on the Pixel 7 project (412 px wide, same phone layout as 375).
