# #66 Completing a task with its checkbox drops keyboard focus to <body>
Status: done
PR: pending
Summary: `toggleKeepingFocus(id)` (exported from `src/hooks/useHotkeys.ts`) is now the one path for `x`, Space on a row and the row checkbox when the focus is in that row. A completed row that leaves the list hands focus to the next row (the previous one if it was last). Undoing that completion (⌘Z or the toast) puts focus back on the restored row while the keyboard is in the list.

## What changed
- src/hooks/useHotkeys.ts: `toggleKeepingFocus` (was inline in the `toggle` action), `focusRow` (through `ui.focusedId`, or a direct `.focus()` when the store already points at that row), and a `handedOn` map (undo entry id → task, last 20) read by a task-store subscription in `useHotkeys` that spots an undo (a new entry in `future`).
- src/components/TaskItem.tsx: the checkbox calls `toggleKeepingFocus` when `document.activeElement` is inside its row, otherwise a plain `toggle`.
- e2e/keyboard-rows.spec.ts: Enter and Space on the checkbox → next row focused; ⌘Z → restored row focused; last row → previous row. Fails without the TaskItem change (2 of 3).

## Tried and rejected
- Storing the task id on `UndoEntry`: it would touch every undo entry and the store's types for one focus feature.

## Notes for future agents
- A mouse click focuses the button in Chromium, so a click also moves focus to the next row. That's harmless (no focus ring after a pointer click); Safari doesn't focus buttons on click, so it takes the plain path.
- The order comes from `visibleOrder` for the current view, so Today, By deadline and Week share the path. Only the Tree is covered by e2e.
