# #27 Landing page: content visible without scrolling in, demo out of the Tab order
Status: done
PR: pending
Summary: Below-the-fold landing sections now only rise (no opacity 0) when scrolled in, so the feature cards and closing call to action are visible without the observer firing; the demo card is `inert` inside a `role="img" aria-label="Preview"` wrapper; the header button now says "Continue with Google" like the hero.

## What changed
- `src/landing/LandingPage.tsx`: `Reveal` has an `immediate` mode (hero: fade + rise on mount, no
  IntersectionObserver). Other sections start from a `rise` variant (y offset only, opacity
  untouched). Header sign-in label is "Continue with Google".
- `src/landing/DemoCard.tsx`: `.stage` is `role="img" aria-label="Preview"`; the card inside is
  `inert` (spread as `{ inert: '' }` because React 18 has no typed boolean `inert`).
- `src/landing/LandingPage.test.tsx`: tests for visible-by-default sections (fails on the old
  code), the inert preview, and the single sign-in label.
- `e2e/landing.spec.ts`: looks for `img "Preview"` instead of `group "Interactive demo"`.

## Tried and rejected
- `initial={false}` on below-fold sections: removes the motion entirely rather than keeping it
  as an enhancement.
- `inert` on the labelled element itself: inert also hides the label, so the label sits on the
  wrapper outside the inert card.

## Notes for future agents
- The demo is no longer clickable (inert blocks pointer input too). `useDemo`'s toggle/pause
  logic and its tests stay; they are now only used by autoplay.
- When React moves to 19, change `{...{ inert: '' }}` to `inert`.
- Review L3 also suggested dropping the "Free · Private · Synced" chip. Not in this issue's
  "Done when", so it is still there.
