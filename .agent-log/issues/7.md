# #7 Week view: a 7-day calendar tab (Mon–Sun), read-only
Status: done
PR: #15
Summary: Adds a read-only Week tab (one Mon–Sun week, ‹ › Today navigation) built on a pure src/lib/week.ts helper, wired into the switcher, palette, hotkeys and visibleOrder, with unit and e2e tests.

## What changed
- src/lib/week.ts (+ test): weekStart, weekDays (due / planned / carried rows, points per day), weekIds, weekRange. Pure; `today` is always passed in.
- src/components/WeekView.tsx (+ css): one week at a time. 7 columns from 1024px; below that a vertical list (cards, then sticky sections at ≤480px). Header: weekday, date, points (always shown, dimmed at 0). Today's column highlighted.
- TaskItem: `quiet` (planned row: hollow marker in theme.css, muted title) and `compact` (title wraps to 3 lines, hover strip keeps only ⋯, no breakdown nudge, tighter padding ≥1024px only).
- ui store: `week` view + `weekAnchor` (Monday shown; null = follow today; not persisted). Switcher, palette "Go to Week", hotkey 5 (4 with Today off), shortcuts list.
- views.ts visibleOrder: Week rows in day order (a task on two days once).
- e2e/week.spec.ts: due days land in the right columns, points, check + Undo, next week / Today, palette, no sideways scroll on phone. Dates come from the browser clock, so it passes on any day.

## Tried and rejected
- 7 columns from 768px (issue's breakpoint): at 768–1023 a column is ~96px and words like "Groceries" break mid-word. The issue only fixes <768 (list) and desktop (7 columns), so desktop starts at 1024.
- Full hover strip in narrow columns: it covered the checkbox (e2e click failed).
- Compact padding on phones: pushed the difficulty icon 2px past the screen edge and widened the page.
