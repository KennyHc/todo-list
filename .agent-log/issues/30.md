# #30 Undo toast: longer window and no overlapping toasts
Status: done
PR: pending
Summary: The undo toast now stays up 8 s (was 5 s); a newer action swaps the label and restarts the timer inside the same card instead of cross-fading a second card on top; ⌘Z Undo is listed under General in the "?" sheet.

## What changed
- `src/components/UndoToast.tsx`: card keyed `"undo"` (stable), so AnimatePresence only animates show/hide; label and timer bar are keyed by entry id, so a new action fades the label in and restarts the bar. Duration comes from `UNDO_MS = 8000`, set inline as `animation-duration`.
- `UndoToast.module.css`: fallback duration 8 s; dropped the "swapping toasts overlap" comment.
- `src/lib/shortcuts.ts`: `Undo` (`mod`+`Z`) under General.
- Tests: new `UndoToast.test.tsx` (8 s timer, dismiss on animationend, one card on rapid actions, ⌘Z) and `src/lib/shortcuts.test.ts`.

## Tried and rejected
- `AnimatePresence mode="wait"`: no overlap, but delays every replacement toast by the exit animation.
- A stack of several toasts: needs a multi-entry undo store, which the issue puts out of scope.

## Notes for future agents
- The store API (`undo`, `undoLast`, `dismissUndo`) and `toggle` are unchanged.
- Sibling elements inside the card must not share a key: label and bar use `label-<id>` / `bar-<id>`. With the same key React kept the old label in the DOM.
- jsdom never fires CSS `animationend`; tests fire it by hand on the bar.
- Not checked visually in a browser; covered by unit tests only.
