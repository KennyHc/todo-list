# #74 Hotfix: checking a subtask also checks its parent
Status: done
PR: #75
Summary: Toggling a row with its own checkbox or swipe never moved the selection (`ui.focusedId`), so with the parent row selected, the next `x` or Space completed the parent and all its subtasks. Now, when a row is selected, the toggled row becomes the selected one (and focus moves on as in #66), so keys act on it or on the row that took its place.

## What changed
- src/components/TaskItem.tsx: new `toggleHere` callback, used by the Checkbox and SwipeRow `onComplete`. With a row selected it sets `focusedId` to this row, then calls `toggleKeepingFocus`. With nothing selected it keeps #66's behaviour (`toggleKeepingFocus` if the focus is in the row, else plain `toggle`). `toggleDone` and `reevaluateFrom` are unchanged.
- src/components/App.test.tsx: 4 tests (Tree + x, Tree + Space, Week + x, all subtasks → parent done). The first 3 fail without the fix.
- e2e/subtask-done.spec.ts: click + x/Space, x/Space on a focused subtask, Week + x, tap + x and swipe + x (phone), and all subtasks → parent done. Without the fix, Week and swipe fail. In Chromium the click and tap cases are masked by #70: a click there focuses the button, so focus already moved on.

## Reproduced (HEAD fa7b4ad and the deployed 92842d8)
- No single action is broken. Click, Space or `x` on a focused subtask, touch tap, swipe, a fast double-click, and Today and Week each complete only that subtask.
- Broken: select the parent, check a subtask with the mouse, tap or swipe, then press `x` or Space → the parent and every subtask end up done. On 92842d8 this happens in every view and browser. On HEAD it still happens in Week (done rows stay listed), after a swipe, and in Safari or jsdom, where a click doesn't focus the button.

## Tried and rejected
- Changing the tree logic: it is correct, and "all subtasks done → parent done" must stay.
- Selecting the row on every checkbox click, even with nothing selected: it would add a focus ring for mouse-only users. Not needed for the fix.

## Notes for future agents
- e2e: the closed "Task options" menu stays in the DOM while it animates out, and hotkeys ignore keys while any `[role="dialog"]` exists. Wait for `[role="dialog"]` count 0 before pressing keys.
- Week only moves the DOM focus to a selected row from nowhere or from another row, so assert `data-focused`, not `toBeFocused`.
