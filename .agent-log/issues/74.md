# #74 Hotfix: checking a subtask also checks its parent
Status: needs review
PR: #75, #78, #79
Summary: The user's rule (relayed by the master): "ANY task should only clear its children, and not the parent." Completing a task now completes it and its subtasks only; no check, delete, move, indent, outdent or import ever completes a parent. Reopening still reopens done ancestors.

## What changed
- #75/#78: a checkbox or swipe toggle moves the selection to the toggled row, so a following `x`/Space can't complete a selected parent (`toggleHere` in TaskItem.tsx).
- #79, src/lib/tree.ts: `reevaluateFrom` → `reopenFrom`, which only reopens a done task holding an open child. `toggleDone` no longer walks up on completion; `deleteTask`/`outdentTask` don't touch the old parent; `indentTask`/`moveTask` only reopen the new one.
- src/store/tasks.ts: toggle only spawns repeats for the task and its subtasks; History comment updated. src/lib/recur.ts uses `reopenFrom`.
- src/lib/ai.ts: import completes any task marked `done` (parents first), since a parent no longer derives done from its leaves.
- TaskItem.tsx/.module.css: removed the ancestor auto-complete pulse and its `.flash` overlay. HistoryList: "auto" tooltip now "Completed along with its parent task".
- src/landing/useDemo.ts: the demo checks the 3 subtasks, then the parent.
- Tests: unit (tree, history, ai, store, App, landing) and e2e (cascade-undo, subtask-done) now assert "all subtasks done → parent stays open", plus "a parent's own check completes its subtree". 19 fail on the old logic.

## Reproduced
- The live report (one checkbox click checks the parent) matches the old rule completing a parent with its last open subtask; the user confirmed they want no parent to complete that way. A 4,000-tree fuzz over corrupted shapes (childIds/parentId mismatch, hidden, collapsed, tag filter, repeats) found no other path that completes a parent.

## Tried and rejected
- Keeping "all subtasks done → parent done" (#75's assumption): the user doesn't want it.
- Rewriting stored data: existing done parents are left as they are.

## Notes for future agents
- e2e: closed menus stay in the DOM while animating out and hotkeys ignore keys while any `[role="dialog"]` exists; wait for count 0. Week: assert `data-focused`, not `toBeFocused`.
- Before testing by hand on a localhost port that once served `vite preview`, unregister its service worker (it served pre-#70 code to the master on 286d55f).
- Suspected sync race (CI run 41892273681): `applyPending` runs 25 ms after a snapshot, so a stale server copy queued just before `flush()` sets `last` can be applied over a local edit. Worth its own issue.

## Decided
- User confirmed: reopening a subtask under a done parent reopens the parent and its done ancestors; adding a subtask to a done parent reopens it too. Both unchanged, both tested.
