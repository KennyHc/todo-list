# #49 Composer: a syntax hint for #tag, !1–5, dates and repeats
Status: done
PR: #53
Summary: The composer toolbar gets a "?" button (aria-label "Typing shortcuts", last in the row, same 26/36px height as Tag and Due date) that opens an anchored popover listing tag, difficulty, due date, repeat and "Hidden until" shorthand with an example each; Esc, a click outside or the button closes it and focus returns to the button.

## What changed
- src/components/SyntaxHint.tsx (+ .module.css): `SYNTAX_HINTS` (name, token kind, literal forms, example) and the popover body. Only forms `parseQuickAdd` already parses.
- src/components/TaskInput.tsx: third panel `'syntax'`, a `.syntaxBtn` at the end of the toolbar (`margin-left: auto`), and a `Popover` (`align="end"`, `sheetOnMobile={false}`, so #44's full-width phone rule applies).
- src/components/SyntaxHint.test.tsx: every form must parse as `Task <form>` to exactly its kind with title "Task"; every example must contain its kind; the "from … by …" example gives start and due dates. Component tests cover opening, Esc with focus return, and toggling.

## Tried and rejected
- A cycling placeholder: the composer already cycles four examples (`PLACEHOLDERS`), and it can't list the syntax or be read by a screen reader.
- A hint line under the field: it would change the phone composer's height, which #25 pads the list by.

## Notes for future agents
- If the parser gains vocabulary, add it to `SYNTAX_HINTS`; the test fails if a listed form stops parsing.
- The toolbar only shows while the composer has focus or content, so the "?" is only reachable from there (Tab from the field: Tag, Due date, ?).
- To run the app in a worktree: copy `.env.local` from the main checkout. To sign in, run the Auth emulator alone (Docker holds :8080, where the Firestore emulator would go), start Vite with `VITE_USE_EMULATORS=1`, then call `window.__e2e.signIn('x')`.
