# #37 Phone: Google sign-in returns to the landing page signed out
Status: done
PR: #38
Summary: Installed PWAs (`display-mode: standalone` or iOS `navigator.standalone`) now sign in with `signInWithRedirect` (setting the `auth-redirecting` marker so `initAuth` fetches the result); browser tabs keep popup-first with the redirect fallback; `.env.example` and the README say authDomain must equal the hosting domain (`writeitdown.web.app`).

## What changed
- src/store/auth.ts: new exported `isStandalone()`; `signInWithGoogle` redirects straight away when it is true; comments explain why authDomain must be the hosting domain.
- src/store/auth.test.ts: tests for standalone (matchMedia and navigator.standalone) → redirect + marker, marker cleared on failure, result handled on return, and the browser-tab popup path (touch included).
- .env.example, README.md: authDomain must equal the hosting domain; the handler URI must be an authorized OAuth redirect URI.

## Tried and rejected
- Redirect on every phone browser tab: the cross-domain handoff was the cause, not the popup; with a same-origin authDomain the popup works in tabs, and the issue asks to keep popup-first there.

## Notes for future agents
- The real fix is config: the owner's `.env.local` must have `VITE_FIREBASE_AUTH_DOMAIN=writeitdown.web.app`, and `https://writeitdown.web.app/__/auth/handler` must be an authorized redirect URI. Code alone does not fix production.
- The delete-account re-auth (`src/sync/deleteAccount.ts`) is unchanged: popup first, redirect on `auth/popup-blocked`. In an installed PWA it may hit the same popup problem; worth an issue if phones report it.
- Production moved to the `writeitdown` Hosting site (`firebase.json` `hosting.site`). The old `tasks-app-956r6.web.app` site will redirect to it; the master deploys that redirect, so it is not in the repo. `writeitdown.web.app` must also be a Firebase Auth authorized domain.
- Still on the old domain, left out of scope: `index.html` og:url/og:image and the `?add=` tip in `SettingsPopover.tsx` (+ its test).
- Not verifiable on a phone before deploy; the owner checks after the master redeploys.
